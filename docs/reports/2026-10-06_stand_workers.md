# Отчёт: миссия «Параллельный запуск по стенду» (docs/missions/2026-10-06_stand_workers.md)

Миссия (поле `stands.workers` → `pytest -n <workers>`) уже реализована и
смержена в этой ветке предыдущими задачами. Эта задача — документация:
README и итоговый отчёт, код и тесты не менялись.

## Что сделано по пунктам миссии

1. **Колонка `stands.workers`** — реализовано. `stands.workers INTEGER NOT
   NULL DEFAULT 0` с миграцией через `_migrate_add_column` (по образцу
   `runs.mobile`). `workers: Optional[int] = Field(default=None, ge=0,
   le=16)` в `StandCreate`/`StandUpdate` (`app/schemas.py:49,58`).
   `create_stand`/`update_stand` и `_stands_for`/`_stand_payload`
   (`app/routers/projects.py`) читают, пишут и отдают `workers` в ответах
   API стендов; при создании без явного значения — `0`, при обновлении без
   явного значения — старое значение сохраняется.
2. **Раннер** — реализовано в `app/core/runner.py::_execute` (строки
   574–580): если `stand["workers"]` положителен, **и** прогон не `live`,
   **и** `repeat <= 1` — к `args` добавляется `["-n", str(workers)]` сразу
   после `-m`. Условие и причина (эфир перемешивает кадры нескольких
   воркеров; флаки-детектор гоняет одну цель последовательно и сравнивает
   прогоны между собой) записаны в комментарий прямо над веткой кода — то,
   что просила миссия как докстринг.
3. **UI формы стенда** — числовое поле «Потоки (pytest -n)» в форме стенда
   (`ui/admin.js`, `#stand-workers`): читается при открытии формы на
   редактирование (`data-workers`), входит в payload submit как
   `parseInt(..., 10)` с дефолтом `0` при пустом значении. В списке стендов
   строка с именем получает пометку `×N`, если `workers > 0`
   (`ui/admin.js:52`).
4. **Тесты** — `tests/test_stand_workers.py`: миграция колонки на старой БД
   без неё и на свежей БД, `-n <workers>` в args при `workers>0`, отсутствие
   `-n` при `workers=0`, отсутствие `-n` при `live=true` или `repeat>1`
   даже при `workers=4` (реальный pytest-подпроцесс на фикстурном проекте,
   `-n` проверяется через `config.option.numprocesses` в `probe.json`, как
   это делает pytest-xdist), API create/update принимает и возвращает
   `workers`, смоук формы стенда и бейджа `×N` в `ui/admin.html`/`ui/admin.js`.
5. **README** — сделано этой задачей: абзац про поле «Потоки (pytest -n)» в
   разделе «Sentry» (там же, где уже описана форма стенда с url/login/
   sentry-полями) — диапазон 0..16, `0` = последовательно, ограничения по
   `live`/`repeat`, пометка `×N` в списке стендов.
