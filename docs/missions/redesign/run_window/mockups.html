Окно прогона · вариант а «Кинолента»

Крупный текущий кадр UI-теста + полоска миниатюр по реальным шагам allure (статус каждого шага и его название — подлинные из прогона #39), под кадром — консоль этого шага/теста. Сверху — горизонтальная лента тестов прогона со статусами для переключения.

Окно прогона · вариант б «Сплит»

Слева — полный список тестов прогона (307 шт., реальные статусы/длительности), активный подсвечен. Справа — окно теста с вкладками «Кадры» (картинка для UI-теста), «Консоль» (вывод pytest по этому тесту) и «Запросы» (HTTP-строки, подсвеченные по методу/коду ответа).

Окно прогона · вариант в «Терминал»

Консоль на весь блок — главный объект внимания; вкладка «Экран» переключает на кадр для UI-теста. HTTP-методы и коды ответов подсвечены прямо в потоке вывода pytest (реальные строки run_events, замаскированные раннером). Лента тестов — сверху, компактной строкой чипов.

Карта покрытия · вариант а «Дерево разделов»

Дерево реальных разделов проекта (tests/api/<область>, tests/ui/<область>, tests/e2e — единый раздел «smoke»), у каждого — полоска долей API/UI/smoke (оттенки цвета проекта) и точка статуса по факту последнего прогона #39 (худший статус тестов области).

Карта покрытия · вариант б «Сетка страница × тип теста»

Heatmap: строки — реальные страницы фронтенда (routes.tsv + то, что реально открывают UI-тесты), столбцы — API/UI/E2E. В ячейке — число покрывающих тестов; цвет — их статус в прогоне #39 (зелёный/красный/жёлтый), пусто — не покрыто.

Карта покрытия · вариант в «Санбёрст маршрутов»

От корня проекта — кольцо реальных областей API (по первому сегменту пути после /api/v1/, доля дуги = число маршрутов), дальше — кольцо из 595 реальных маршрутов routes.tsv; серый сегмент — маршрут без единого покрывающего теста, цветной — покрыт.

Источник данных. docs/missions/redesign/run_window/collect_data.py --repo /Users/andreykorotkow/PycharmProjects/test_hub — читает реальные workspace/test_hub.db (прогон #39 проекта auto_tests_vshgu_cloude, 2026-09-28, 307 тестов), workspace/allure-results/39/*-result.json (длительности/сообщения/шаги), workspace/sections/auto_tests_vshgu_cloude/sections.json и workspace/coverage/auto_tests_vshgu_cloude/coverage.json (595 маршрутов, 84 покрыто; 56 страниц, 18 покрыто). В этом worktree сама БД пуста (свежий git worktree, см. соседние мокапы redesign/v2 и redesign/variants) — скрипт указывает на рабочий репозиторий явно, ничего не выдумывая.
Чего не хватает для этапа 2 (код). 1) Кадров UI-теста по шагам нет вообще — раннер гоняет pytest с HEADLESS=1, run_events хранит только текстовые строки; предлагается плагин pytest в проекте автотестов, который на каждый allure-шаг шлёт скриншот в test_hub (или хотя бы по факту падения). 2) Видео/трейс Playwright после теста raннер сейчас не сохраняет и не отдаёт — нужно точку сохранения в conftest проекта + отдачу файла через test_hub. 3) Консоль конкретного теста «на лету» pytest не пишет для прошедших тестов (только результат-строка) — представленные примеры честно показывают это ограничение; для этапа 2 нужен разбор вывода pytest по nodeid в реальном времени (или запуск с --capture=no точечно для выбранного теста). 4) Статус покрытия по методам/кодам ответа сейчас не хранится структурированно — подсветка HTTP в консоли в этом мокапе сделана регэкспом по тексту лога, не по данным.
