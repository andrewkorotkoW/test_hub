# Время ожидания в очереди прогонов (ETA) — 28.10.2026

Запрос владельца: «добавим время ожидания в очередь; вопрос — как оно будет
рассчитываться; сначала макет». Макет (артефакт «Очередь test_hub: ETA») одобрен
28.10 — три места в интерфейсе и карточка с расчётом; реализовано в тот же день.

## Что сделано

- `app/core/eta.py` — кэш медиан wall-time по (стенд, nodeid) из `run_events`
  (`test_start`/`test_end`), overhead прогона, медианы по типу, история той же
  цели (`signatures`), раскрытие цели в nodeid (`select_nodeids`: каталог/файл/
  класс/nodeid, опции `--ignore=` не фильтруют), `estimate_run`,
  `remaining_running` (темп + `overdue`), `queue_eta`, `estimate_for_form`,
  `recalc_async`/`on_run_finished` (хук `runner.register_finalize_hook`).
- API: поле `eta` у running/queued в `GET /api/projects/{name}/runs`;
  `GET /api/runs/{id}/eta`; `POST /api/projects/{name}/eta` («ваш запуск»);
  `POST /api/projects/{name}/eta/recalc` (qa/admin).
- UI: баннер очереди на «Запуске» (список очереди + «Ваш запуск»), колонки
  «Результат»/«Длительность» у активных прогонов во вкладке «Прогоны»,
  `#run-eta` в шапке окна прогона (опрос раз в 15 с).
- Тесты: `tests/test_eta.py` (9), `tests/js/test_runs_history_logic.js`
  (fmtEta/approx/etaCells/ownRunText).

## Факты, определившие метод

- allure `duration` — только тело теста: на прогоне #100 это 3 482 с из 7 803;
  wall-time по событиям раннера на #104 даёт 296 с при длительности 297 с.
- Коэффициент вариации wall-time одного теста между прогонами ≈ 0.9 — отсюда
  «≈», минуты без секунд, вилка ×0.7…×1.5 и пометка «грубо».
- Проверка на живой очереди (прогоны #107–#111 на стенде 2420): баннер,
  история и окно прогона показывают позицию/старт/финиш; оценки на реальных
  данных — набор SCORM ≈ 5 мин при факте 4:15, весь проект ≈ 2 ч 25 мин при
  факте 2 ч 10 мин. Стенд 2420 в этот момент лёг (404), прогоны отменены.

## Ограничения

- Очередь общая на проект: прогон на другом стенде задерживает ваш.
- Маркер `-m` по nodeid не применяется — оценка грубая, пока у той же цели с
  маркером не наберётся 2 прогонов.
- Упавший стенд (все тесты по таймауту с повторами) раздувает медианы на
  5 следующих прогонов стенда — окно HISTORY_RUNS.
