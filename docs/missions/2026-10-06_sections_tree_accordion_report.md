## Что сделано (t1, по коду — `ui/sections-tree-logic.js`, `ui/project.js`)

- Дерево на вкладке «Запуск» и в форме «Новое расписание» (общий `createSectionsPicker`)
  стало аккордеоном: узлы раздел (`tests/api`/`tests/ui`/`tests/e2e`) и область внутри
  него по умолчанию свёрнуты, разворачиваются кликом/Enter/Space по заголовку. Раскрытые
  вручную узлы переживают пересборку разметки при поиске/пресете/отметке чекбокса.
- Заголовок узла показывает человекочитаемое имя, число тестов (+ % passed, если есть
  статистика) и счётчик «выбрано N из M».
- Имена областей/файлов — человекочитаемые (`AREA_LABELS_RU` для известных + авто
  `snake_case → Snake case` для остальных; у файлов убираются `test_`/`.py`), путь
  остаётся в `title`.
- Поиск на время непустого запроса принудительно раскрывает узлы с совпадением, не
  трогая набор раскрытых вручную.
- Кнопки-пресеты (API/UI/Smoke/Всё на «Запуске», API/UI/Всё на «Расписаниях» — Smoke там
  не нужен) стали переключателями с подсветкой активного и строкой итога «Выбрано: N
  файлов · API X · UI Y[· E2E Z][· маркер: smoke]».

### Известное ограничение (не исправлено)

После клика по пресету «Smoke» `<select id="marker-select">` получает значение
`smoke`. При последующем переключении на любой другой пресет (API/UI/«Всё») это
значение **не сбрасывается**: подсветка активной кнопки и строка итога корректно
показывают новый пресет без маркера, но сам select молча остаётся на `smoke` и в
этом виде уходит в `submit_run`/создание расписания. Воспроизведено и подтверждено
записью `runs.marker='smoke'` в БД при выбранном пресете «Всё». Причина — выбор
пресета в `createSectionsPicker` (`ui/project.js`) выставляет `markerSelectEl.value`
только в ветке `preset === "smoke"`, обратного сброса для остальных веток нет.
Решение откладывается на следующую задачу (в исходном отчёте t3 — «для Пэм/t4»).
