# Миссия: «Эфир» — живая трансляция UI-теста в окне прогона + видео каждого теста

Записано 01.10.2026 по решению владельца: «хочу видеть онлайн, как проходит тест, а не скрины».
Парная миссия в проекте автотестов: `auto_tests_vshgu/docs/missions/2026-10-01_live_stream_plugin.md`
(плагин шлёт кадры и видео). **Контракт ниже — общий для обеих миссий, менять только синхронно.**

## Уточнение владельца 01.10: эфир — только для выбранных прогонов

Эфир не включается для всех прогонов. У прогона появляется флаг `live` (bool, по умолчанию
false): колонка `runs.live` (миграция), поле `live` в `POST /api/projects/{name}/runs`, галочка
**«Эфир»** в форме запуска рядом с «Запустить выбранное» и в ручном вводе целей, и на странице
сборки (этап 2 миссии 8762067a). При `live=true` раннер передаёт pytest env `TH_LIVE=1`
(иначе не передаёт, плагин трансляцию не запускает). Вкладка «Эфир» и «Следить за прогоном»
показываются только у прогонов с `live=true`. Полные и ночные прогоны по расписанию — без эфира.
Видео теста пишется у всех прогонов независимо от флага.

**Лимит по числу тестов (владелец, 01.10):** эфир разрешён, только если в прогоне не больше
`TH_LIVE_MAX_TESTS` тестов (env test_hub, по умолчанию 20). В форме запуска число выбранных
тестов считается по дереву/ручному вводу до отправки: при превышении галочка «Эфир»
недоступна с подсказкой «Эфир доступен для прогонов до 20 тестов, выбрано 57». Сервер
дублирует проверку: `POST …/runs` с `live=true` и числом целей больше лимита → 422 с тем же
текстом (число тестов в целях сервер знает из `runner.discover`, как для дерева).

## Контракт плагин → test_hub

1. `POST /api/runs/{run_id}/live` — живой кадр. Заголовок `Authorization: Bearer <TH_RUN_TOKEN>`
   (как у `/frames`). multipart: `nodeid` (str), `ts` (float, time.time() отправителя),
   `step` (str, имя текущего шага или пусто), `file` (image/jpeg, ширина ≤ 960). Ответ 204.
   Сервер **не пишет кадр на диск**: держит последний кадр прогона в памяти
   (`{run_id: {nodeid, ts, step, jpeg_bytes}}`) и рассылает подписчикам WebSocket прогона
   сообщение `{"type":"live","nodeid":…, "ts":…, "step":…, "jpeg_b64":…}`. Если кадры приходят
   чаще 5 в секунду — лишние отбрасывать (последний побеждает), чтобы не забить сокет.
   Плагин по умолчанию шлёт ~3 кадра/с (`TH_LIVE_FPS`), лимит на стороне сервера — защита.
2. `GET /api/runs/{run_id}/live.jpg` — последний кадр (для страницы share и для
   переподключения): 200 image/jpeg или 404, если кадров ещё не было / прогон завершён более
   5 минут назад (память чистится).
3. `POST /api/runs/{run_id}/tests/{nodeid:path}/video` — видео теста после его завершения.
   multipart: `file` (video/webm), `duration_ms` (int). Хранение:
   `workspace/runs/<run_id>/video/<sha1(nodeid)>.webm` (рядом с кадрами шагов), в БД —
   таблица `run_test_videos(run_id, nodeid, path, duration_ms, size, created_at)`, миграция
   в `app/db.py`. Лимит размера — `TH_VIDEO_MAX_MB` (по умолчанию 50), больше — 413 и запись
   в лог сервера, тест не страдает. `GET /api/runs/{run_id}/tests/{nodeid:path}/video` отдаёт
   файл (Range-запросы поддержать, иначе перемотка в `<video>` не работает).
4. `GET /api/runs/{run_id}/tests` в каждом элементе получает `has_video: bool`.
5. Share-страница (`/share/<token>/`) показывает видео и последний живой кадр так же, как
   основное окно, без авторизации (токен share уже даёт доступ к прогону).

## Окно прогона (ui/project.js, вид «Сплит»)

1. Новая вкладка **«Эфир»** у выбранного теста: показывается, когда прогон идёт и по тесту
   приходят live-кадры. Картинка обновляется из WS-сообщений `live`; сверху бейдж «В эфире»
   и имя текущего шага; если кадров нет 5 секунд — бейдж «нет сигнала» (тест API или
   браузер закрыт). После завершения теста вкладка «Эфир» скрывается, вместо неё «Видео».
2. Переключатель **«Следить за прогоном»** (по умолчанию включён, пока прогон идёт):
   при `test_start` окно само выбирает запущенный тест и открывает «Эфир»; если пользователь
   вручную выбрал другой тест — слежение выключается до повторного включения.
3. Вкладка **«Видео»**: `<video controls>` с записью теста, длительность, кнопка «скачать».
   Есть у тестов с `has_video`.
4. Порядок вкладок: Эфир (во время) / Видео (после) → Кадры → Консоль → Запросы → Sentry.
   Кадры по шагам остаются как есть — они идут в allure и в тест-кейсы.
5. Прогон, открытый по прямой ссылке `?run=<id>`, прокручивает страницу к карточке прогона
   (сейчас остаётся наверху на дереве тестов — замечание владельца 30.09).
6. Тур (`ui/tour.js`): шаг про окно прогона дополнить «Эфиром».

## Ограничения и проверки

- Память: живые кадры только в памяти, не более одного на прогон; чистить при завершении
  прогона через 5 минут и при старте сервера.
- Демо-проект: у демо-прогона добавить 1–2 коротких видео-заглушки (webm 2–3 с, сгенерировать
  скриптом в `demo/`, не коммитить бинарники > 200 КБ) — чтобы вкладка «Видео» была видна в туре.
- Тесты: приём live-кадра и рассылка в WS (мок-клиент), троттлинг 5 кадр/с, загрузка и отдача
  видео с Range, миграция, `has_video`, share без авторизации. UI-логика выбора вкладок и
  слежения — в `*-logic.js` с unit-тестами.
- README: раздел «Окно прогона» дополнить «Эфир» и «Видео», переменные `TH_VIDEO_MAX_MB`.
- Сервер перезапускает владелец. Прогоны на стендах не запускать.
