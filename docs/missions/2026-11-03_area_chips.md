Записано 03.11.2026 по решению владельца: «по твоему макету вот так при выборе» → «да, новую
миссию для Майкла». Макет — блок дерева в `docs/missions/redesign/product_presets/mockups.html`

развёрнутого дерева файлов — строка на каждый вид (`tests/api`, `tests/ui`, `tests/e2e`) с
чекбоксом-тристейтом и счётчиком, а под ней области плашками с числом тестов; выбранные
плашки подсвечены, невыбранные приглушены. Делать по макету, не выдумывать другую раскладку.

## 1. Вид «области плашками» в форме запуска и расписания

`ui/project-sections-picker.js` (рендер), `ui/sections-tree-logic.js` (чистая логика),
`ui/project.html`, `ui/style.css`.

- Для каждого вида (`kindNode`) — строка: стрелка раскрытия, чекбокс-тристейт (все файлы вида /
  часть / ничего), название `tests/<kind>`, мета «N тест. · выбрано M» моноширинным.
- Под строкой — плашки областей (`area.area`, у `tests/e2e` без области — одна плашка
  «e2e»): текст `<area> <tests_count>` моноширинным 11.5px, скруглённые, рамка `--border`;
  состояние `on` (все файлы области отмечены) — заливка `color-mix(--accent 22%)`, рамка
  `--accent`, текст `--text`; `partial` (часть файлов) — рамка `--accent` без заливки; `off` —
  прозрачная, при наличии хоть одного выбранного в форме — `opacity .45`. Цвет — `--accent`
  (цвет проекта) допустим: это подсветка выбора, а не категория (решение владельца про ряд
  «Что» относится к кнопкам продуктов, не к плашкам).
- Клик по плашке переключает все файлы области (on → off, иначе → on). Клик по чекбоксу вида
  — все файлы вида. Стрелка раскрывает под плашками существующее дерево файлов/классов (как
  сейчас) для точечного выбора; по умолчанию свёрнуто. Пресеты «Что»/«Как» просто меняют
  набор отмеченных файлов — плашки и тристейты пересчитываются из `checked`, отдельного
  состояния у них нет.
- Поиск по разделам фильтрует плашки (и дерево под ними) по подстроке, как сейчас фильтрует
  дерево. Ручной ввод nodeid — без изменений.
- Форма расписания — тот же пикер (`createSectionsPicker`), ничего не копировать.
- Чистая логика в `sections-tree-logic.js`: `areaState(area, checked) -> "on"|"partial"|"off"`,
  `kindState(kindNode, checked)`, `toggleArea(area, checked) -> Set`, `toggleKind(...)`.

## 2. Один файл — один раз в счётчиках

**Факт 03.11:** раздел `tests/e2e` в дереве (`GET /api/projects/{name}/sections`) собирается по
маркеру `e2e`, поэтому 21 файл из `tests/ui/<area>` числится дважды — в своей области и в
`e2e` (`tests/ui/courses/.../test_user_scorm_stream_flow.py`: `ui/courses:1` и `e2e/∅:1`).
Отсюда три разных числа у LMS: 264 на кнопке (`productTestCounts`, сумма по областям с
дублями), 262 у `presetLeafTargets(lms)` по уникальным файлам, 267 в строке итога
(`countCheckedByKind` считает файл в каждом виде, где он встречается).

- `productTestCounts`, `countCheckedByKind`, мета строк вида и счётчики плашек считают
  каждый `file.target` один раз (Set по target); для `tests/e2e` показывать число как есть
  (это и есть «тесты с маркером e2e»), но в «Выбрано: N тестов» файл учитывается один раз.
- Кнопка «Всё» должна показывать число уникальных тестов проекта, а не 479 с дублями;
  «LMS» + «Helpdesk» + «LRS» + Integration = «Всё».
- Node-тесты: дерево с файлом в двух видах → все три счётчика сходятся; `areaState`/
  `toggleArea` на on/partial/off; тристейт вида.
