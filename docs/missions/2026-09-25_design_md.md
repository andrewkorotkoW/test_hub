## Часть 1. `DESIGN.md` для cyber_office

- Токены из `ui/style.css`: три темы `arcade` (по умолчанию), `gameboy`, `cyberpunk` — каждая как
  набор поверхностей/текста/акцента/линии; цвета персонажей из `app/core/roster.py`
  (michael #4f8cff, dwight #ff9a3c, pam #ff4fa3, oscar/ralph #39ff88); неон-свечение кнопки сводки;
  палитра статусов задач (todo/running/review/done/failed) и событий; спрайты этажа (`ui/floor.js`)
  — пиксельная стилистика, размеры столов/персонажей.
- Разделы прозой: «офис как игра»: пиксельные портреты 256×256, реплики над головами, три темы как
  «скины», мобильная раскладка ≤768px, доступность (reduced-motion), русские подписи.
- Do's/Don'ts: не добавлять четвёртую палитру в JS; тема — только через `[data-theme]` и токены;
  свечение — только для «требует внимания».

## Часть 2. Офис подаёт DESIGN.md агентам

- `app/core/runner.py` (или где собирается промпт задачи): если в репозитории задачи есть
  `DESIGN.md` и задача затрагивает UI (в заголовке/описании есть ui/дизайн/страниц/css/html/макет,
  либо репозиторий помечен `ui: true` в repos.json), в промпт добавляется блок
  «В репозитории есть DESIGN.md — дизайн-система проекта. Следуй ему строго: цвета, шрифты, радиусы,
  компоненты только из токенов; при расхождении с текущим CSS приводи CSS к DESIGN.md, а не наоборот.»
  Сам файл не вставлять целиком (он и так в репозитории), только ссылку и правило.
- Планировщик миссий (`app/core/planner.py`): для миссий про дизайн/UI в описание задач добавляется
  та же ссылка.
- UI офиса: в карточке репозитория бейдж «DESIGN.md» если файл есть.

## Часть 3. Проверка файла

- Node в системе старый (v12), `npx @google/design.md lint` не запускается — написать свой
  минимальный линтер `app/core/design_md.py`: front matter парсится (pyyaml уже в зависимостях? если
  нет — простой разбор `key: value` без новых зависимостей), обязательные ключи `name`, `colors`,
  ссылки `{a.b}` указывают на существующие токены, hex-цвета валидны, разделы `##` в допустимом
  порядке. Команда `python -m app.core.design_md lint <path>`.
- Тесты: линтер на фикстурах (валидный, битая ссылка, плохой hex); проверка, что
  `DESIGN.md` офиса и test_hub проходят линтер; runner добавляет блок для UI-задач и не добавляет
  для остальных.
