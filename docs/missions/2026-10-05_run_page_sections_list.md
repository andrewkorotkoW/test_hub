## Проблемы сейчас

- Дерево всегда развёрнуто целиком (виды → области → файлы) и занимает всю высоту блока (`.test-tree` 460px
  со скроллом) — длинный список, в котором трудно ориентироваться.
- Файлы подписаны путями/именами файлов (`test_x.py`), а не названиями разделов — пользователю непонятно,
  что за тесты.
- Кнопки API / UI / Smoke / Всё: по клику меняется только состояние чекбоксов где-то внутри длинного
  дерева, сама кнопка не подсвечивается, итога нет — «нажимаем, и ничего не видно, что отобразилось».

## Что сделать

1. **Список, раскрывающийся по нажатию.** Уровни «вид» (`tests/api`, `tests/ui`, `tests/e2e`) и «область»
   делаются раскрывающимися (`<details>/<summary>` или свой аккордеон на кнопках с `aria-expanded`), по
   умолчанию свёрнуты; в заголовке узла — название, число тестов и счётчик «выбрано N из M». Клик по
   чекбоксу узла по-прежнему отмечает всё вложенное; раскрытие и выбор — разные клики (чекбокс не должен
   сворачивать/разворачивать). Состояние раскрытых узлов переживает перерисовку при поиске/пресете
   (сейчас `render()` заменяет `innerHTML` — сохранить набор раскрытых узлов так же, как `snapshotChecked`).
   Поиск по разделам (`#sections-search-input`) автоматически раскрывает совпавшие узлы.
2. **Имена по разделам.** Показывать человекочитаемые названия: для области — `area.section`/`area.area`
   (как в кейсах test_hub: `api/notifications` → «Уведомления (API)», если в проекте есть карта названий —
   `app/core/test_cases.py` / `sections` API — использовать её, иначе аккуратно преобразовать
   `snake_case` → «Snake case»); для файла — имя без `test_`/`.py` и без пути, путь — в `title`.
   Полный `target` остаётся в `data-target`, логика `collectTargets` не меняется.
3. **Сортировка/фильтр API · UI · Smoke с видимым результатом.** Кнопки пресетов становятся переключателями
   с активным состоянием (как `.tabs button.active`): нажатая подсвечена; дерево сортируется/группируется так,
   что выбранный вид идёт первым и раскрывается, остальные сворачиваются (для Smoke — раскрыть все виды,
   выделить файлы со smoke, если бэкенд отдаёт маркеры; если нет — оставить текущую семантику «все + маркер
   smoke», но показать это явно). Под кнопками — строка итога: «Выбрано: 12 файлов · API 8 · UI 4 ·
   маркер: smoke», она же обновляется при ручных кликах по чекбоксам. Кнопка «Всё» снимает фильтр.
   Та же картинка в форме расписаний (`#sched-sections-tree`, `#sched-sections-presets-row`) — picker общий.
4. Тесты: расширить `tests/js/` для `sections-tree-logic.js` (сортировка по виду, счётчики, сохранение
   раскрытых узлов — если вынесено в чистую логику), smoke-UI (`tests/test_project_tabs_ui.py` и соседние):
   узлы свёрнуты по умолчанию, раскрываются кликом, пресет подсвечивается и обновляет строку итога.
   Прогнать `pytest -q tests` и JS-тесты.
