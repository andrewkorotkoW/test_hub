# Миссия: окно прогона во вкладке «Запуск» — этап 2, реализация варианта B «Сплит»

Записано 29.09.2026. Владелец выбрал вариант **B «Сплит»** из
`docs/missions/redesign/run_window/mockups.html` (JPG `run-b-split-*.jpg`). План и список
недостающих данных — `docs/missions/redesign/run_window/README.md` (разделы «Каких данных сейчас
нет» и «План этапа 2»). Открыть макет и README перед началом обязательно.

## Что должно получиться (test_hub)

1. **Разметка вывода по тестам.** Миграция `run_events`: колонки `nodeid TEXT NULL`,
   `kind TEXT NOT NULL DEFAULT 'line'` (`line` | `test_start` | `test_end` | `step` | `frame`).
   Раннер (`app/core/runner.py::_log_line`) распознаёт служебные строки плагина проекта тестов
   вида `[TH] start <nodeid>`, `[TH] end <nodeid> <status>`, `[TH] step <nodeid> <n> <название>`
   и пишет их с `nodeid`/`kind`; обычные строки stdout между `start` и `end` получают
   текущий `nodeid`. Плагина в проекте тестов может не быть — тогда всё как сейчас
   (`kind='line'`, `nodeid=NULL`), ничего не ломается.
2. **Кадры.** `POST /api/runs/{run_id}/frames` (multipart: `nodeid`, `step`, `file` PNG,
   авторизация токеном прогона `TH_RUN_TOKEN`, который раннер генерирует на каждый прогон и
   передаёт в env pytest вместе с `TH_URL` и `TH_RUN_ID`). Файлы — в
   `workspace/frames/<run_id>/<hash(nodeid)>/<step>.png`, запись `kind='frame'` в `run_events`.
   Лимит размера кадра и общего числа кадров на прогон (константы в config), старые кадры
   чистятся вместе с прогоном.
3. **WebSocket** `/ws/runs/{id}` дополнительно шлёт события `test_start`, `test_end`, `step`,
   `frame` (с nodeid). `GET /api/runs/{id}/tests` — список тестов прогона со статусами
   (по событиям, а после завершения — по allure), `GET /api/runs/{id}/tests/{nodeid}/log` —
   строки только этого теста, `GET /api/runs/{id}/tests/{nodeid}/frames` — кадры.
4. **UI, вкладка «Запуск», карточка прогона** — как на макете «Сплит»: слева список тестов
   прогона со статусами, обновляется по мере выполнения, выбранный подсвечен; справа окно с
   вкладками **Кадры** (крупный текущий кадр + миниатюры по шагам; для API-теста и без кадров —
   честная подпись «кадров нет», не заглушка), **Консоль** (строки этого теста, подсветка
   PASSED/FAILED/трейсбеков), **Запросы** (строки консоли, похожие на HTTP: метод, путь, код —
   фильтр на фронтенде). Общий лог всего прогона остаётся доступен переключателем «Весь лог».
   Старые прогоны без разметки показывают только «Весь лог».
5. Токены и компоненты — из `DESIGN.md`; тема и цвет проекта работают.

## Ограничения

- Совместимость: проекты без плагина, старые прогоны, `share`-страница отчёта — не ломать.
- Тесты: миграция, разбор `[TH]`-строк, `POST frames` (лимиты, токен), `GET tests/log/frames`,
  UI-логика без браузера (как `tests/test_project_tabs.py`). Существующие тесты проходят.
- Коммиты небольшие, на русском. Скриншоты `docs/screenshots/run_window_*.png` (обе темы).
